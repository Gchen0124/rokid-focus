# Startup dependency graph

updated: 2026-08-19

Who we are selling to is different, so **proof is different**. Do not serialize everything into one chain.

Wrong single chain (freezes the company):

```
website + Reddit users → 3D → talent → funding
```

That waits on the slowest, noisiest proof. Hardware 好战友 and this week’s accelerator do not buy the same artifact.

## Two audiences, two minimums

| Who | They actually need to see | False gate (do not wait) |
|---|---|---|
| Hardware talent | A **still they can judge**, a **dated sprint** (hackathon), a **split of labor** (they CAD, you software/apply), evidence you already ship (Rokid HUD) | Polished website, Reddit karma, full BP, first check already in the bank |
| Accelerator / first check this cycle | **Apply on time**, clear product sentence, founder + demo link. 3D helps. Team is a bonus, not a prerequisite for SkyDeck-class apps | “We’ll apply once we have a cofounder and users” |
| Later VC / angels | Team + working proto + a path to users | Vanity landing page without a device story |

Talent **does** make later funding easier. That is real. It is **not** a gate on this week’s SkyDeck / hackathon submit. First checks often land **before** the dream hire. The hire then makes the *next* round easier.

## What unlocks what

```
3D still (Codex, one sitting)
  → talent conversation
  → hackathon hardware section
  → slightly stronger accelerator packet

Hackathon apply (hardware track)
  → talent magnet (deadline + name on a thing)
  → accelerator story (“we ship in public”)

SkyDeck / Opportunity DL (clock: 2026-08-21)
  → first-check path
  → talent easier *after* you can say “we applied / we’re in process”
  does NOT wait on talent

Thin site (after a still exists)
  → inbound, a URL for applications
  not a talent gate

Reddit / X / 营销
  → community validation *once there is a render or clip*
  empty posts do not attract a hardware person
  does not unlock SkyDeck this week
```

**Unlock bonus on talent:** 3D + hackathon clock. That is the 0.35× compounding in `RANK.md`, not a new #1.

## Sequence (best, not the longest)

1. **Clock, this week:** SkyDeck if not submitted (Fri Aug 21). Real time, not the 0.01m pin.
2. **One artifact:** 3D still via Codex. Time-box (45–90m). This is the talent bait.
3. **Hackathon hardware fields** as soon as the still exists.
4. **Talent ask:** 10-day sprint, still attached, not “be my cofounder.”
5. **Thin site** only after (2) — one page, the render, the ask.
6. **Reddit/X** only when (2) or a HUD clip exists. Otherwise skip.

BP stays below until there is a teammate line or a submitted packet to point at.

## Judge the user’s hypothesis

“Need 3D / site / users before talent, talent before funding” — **half right**.

- **Keep:** 3D (or equivalent physical proof) before a serious hardware-talent ask. You were right.
- **Drop as a gate:** website and Reddit *before* talent or *before* this week’s apply. Those are amplifiers after an artifact, not tickets to start.
- **Missing piece:** funding clocks and talent run **in parallel**. Waiting for a 好战友 to apply to SkyDeck is how the window closes. Waiting for Reddit to 3D is how the 好战友 never sees you.

## Rule for the next rank pass

If a task is only there to “look fundable,” ask: **fundable to whom, by which date?**  
If the date is this week, ship the apply. If the audience is a hardware person, ship the still. If neither, it is later.
